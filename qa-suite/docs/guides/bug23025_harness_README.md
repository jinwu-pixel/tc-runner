# BUG #23025 검증 하니스 사용 설명서

THOR2 / THOR2-J의 Simple mode에서 "모두 닫기" 후 홈이 빈 화면으로 뜨는 버그(#23025)를 ADB로 자동 재현·검증하는 도구입니다. 여러 시나리오를 반복 실행해 홈 복귀·ANR·빈 화면을 자동으로 판정하고, 문제가 난 순간의 로그와 스크린샷을 모아 줍니다.

파일은 두 개입니다. 실행 본체 `bug23025_close_all_verify.sh`, 더블클릭 런처 `run_bug23025.bat`. 두 파일은 **같은 폴더**에 두세요.

---

## 1. 준비

- Git for Windows(Git Bash 포함) 설치.
- ADB 설치 + 단말 USB 디버깅 켜기. `adb devices`에 단말이 `device`로 보이면 됩니다.
- 단말은 Simple mode 상태, 화면 잠금은 해제 권장.
- (선택) ImageMagick이 있으면 빈 화면 픽셀까지 자동으로 봅니다. 없으면 그 검사만 건너뜁니다.

---

## 2. 실행

`run_bug23025.bat`을 **더블클릭**하면 메뉴가 뜹니다. 차례로 고르면 됩니다.

1. 시나리오 — 기본 / 스트레스 / 전체 / 직접 선택
2. 반복 횟수 (기본 100)
3. 단말 — 한 대면 자동 선택, 여러 대면 번호 선택

끝나면 결과 요약이 나오고, 창은 키를 누를 때까지 열려 있습니다.

명령으로 옵션을 주려면 `.bat` 뒤에 붙이세요. 예: `run_bug23025.bat -S closeall_keymash -n 50` (옵션을 주면 메뉴는 건너뜁니다).

---

## 3. 시나리오

확률성 버그라 횟수가 많을수록 잘 잡힙니다.

**기본 (메뉴 ①)**

| 시나리오 | 무엇을 하나 |
|---|---|
| basic | 앱 여러 개 실행 → 최근앱 → 모두 닫기 (기본 경로) |
| hwkeys | 전화/메시지/연락처/즐겨찾기 키 → 홈 반복 → 모두 닫기 (하드웨어 키 경로, `--hwkeys` 권장) |
| toggle | 최근앱↔홈을 빠르게 누른 뒤 모두 닫기 |
| reentry | 모두 닫기 도중 최근앱 키를 다시 누르기 |
| screenoff | 화면 끈 상태로 최근앱 키 → 바로 홈 |

**스트레스 (메뉴 ②, 옵션)**

| 시나리오 | 무엇을 하나 |
|---|---|
| closeall_keymash | 모두 닫기 직후 여러 키를 빠르게 난타 |
| closeall_switchstorm | 모두 닫기 도중 최근앱 키를 연타 |
| rapid_close_cycle | 최근앱↔모두 닫기를 한 회차에 여러 번 반복 |

`reboot`(옵션)는 재부팅 후 홈이 정상인지 봅니다. 횟수는 적게(예: `-n 3`) 쓰세요. 배터리 완전 방전 부팅·배경화면 변경·플래시 후 첫 부팅은 자동화가 안 되니 손으로 같이 확인하세요.

## 4. 결과 보는 법

동작이 끝나면 화면이 정상인지 자동으로 확인합니다. 스트레스 세 가지(keymash·switchstorm·reentry)는 마지막에 **홈 버튼을 눌러 "홈으로 잘 돌아오는지"** 를 봅니다. 이때 최근앱이 "최근 항목 없음"으로 잠깐 보이는 건 정상이라 PASS입니다.

- **PASS** — 정상.
- **FAIL** (진짜 문제) — 홈으로 못 돌아오고 최근앱/검은 화면에 갇힘, 포커스 없음, ANR. 스트레스에서는 홈 복귀 후에도 빈 화면이면 FAIL.
- **WARN** (사람이 확인) — 느린 복귀, 빈 화면 의심, 최근앱 무반응, 모두 닫기 버튼 못 찾음. → 아래 `artifacts` 폴더의 스크린샷을 직접 보세요.

(듀얼 디스플레이 단말이라 판정은 메인 화면만 봅니다.)

결과는 실행한 폴더 아래 `bug23025_logs/run_날짜시간/`에 쌓입니다.

- `summary.txt` — 시나리오별 PASS/WARN/FAIL 요약
- `results.csv` — WARN/FAIL 목록과 사유
- `logcat_full.log` / `logcat_filtered.log` — 로그
- `artifacts/` — 문제 순간의 스크린샷·덤프. 각 폴더의 `context.txt`(시나리오·회차 자가식별)와 `anr_extract.txt`(전체 logcat에서 뽑은 ANR 라인)도 함께 저장됩니다.

종료코드: FAIL 있으면 1, WARN만 있으면 2, 모두 PASS면 0.

## 5. 자주 막히는 점

- **메뉴가 안 뜨고 바로 basic이 시작됨** → 폴더에 옛 버전 .sh가 있는 경우. 최신 .sh로 덮어쓰세요. (`grep -c maybe_interactive bug23025_close_all_verify.sh`가 0이면 옛 버전)
- **`bad interpreter ... ^M` 에러** → 줄바꿈 문제. `.bat`은 자동으로 고칩니다. 수동이면 `sed -i 's/\r$//' bug23025_close_all_verify.sh`.
- **모두 닫기 버튼을 못 찾음** → `--clearxy x,y`로 버튼 좌표를 직접 지정.
- **하드웨어 키 경로를 제대로 보려면** → `adb shell getevent -lt`로 키코드를 확인해 `--hwkeys`로 넣기.
- **cmd 창 한글이 네모로 보임** → 콘솔 폰트를 한글 지원 폰트(예: D2Coding)로 변경, 또는 Git Bash에서 직접 실행.

## 6. 자주 쓰는 옵션

`.bat`(또는 `.sh`) 뒤에 붙입니다. 전체는 `-h`로 확인하세요.

| 옵션 | 뜻 |
|---|---|
| `-s <시리얼>` | 대상 단말 지정 |
| `-n <횟수>` | 시나리오당 반복 횟수 |
| `-S <목록>` | 실행할 시나리오 (주면 메뉴 생략) |
| `--hwkeys <키코드>` | 하드웨어 키 경로 검증용 키코드 |
| `--clearxy <x,y>` | 모두 닫기 버튼 좌표 |
| `--display <id>` | 판정할 메인 화면 ID (기본 0) |
| `--home <컴포넌트>` | 홈 자동탐지 실패 시 직접 지정 |
| `-b` | FAIL 때 bugreport 수집 |
| `--menu` / `--no-menu` | 메뉴 강제 표시 / 생략 |
