# BUG-23025: [Launcher] Simple mode 에서 최근앱 "모두 닫기" 후 홈이 빈 화면(blank)

> 작성: QA(정) + Claude 분석 / 2026-06-11
> 상태: 구현완료 (기존 bash 하니스 → tests/bug_23025_harness.py 래퍼)

## 1. 메타

| 항목 | 값 |
|---|---|
| 대상 단말 | AT-M140 (THOR2-J), 480x800 |
| OS / 빌드 | Android 14, UP1A.231005.007 |
| 빌드 타입 | user |
| 발생 모드 | Simple mode, 듀얼 디스플레이(main=display 0, sub=com.hnlens.app.subdisplay) |
| HOME | com.hnlens.simplemode/.ui.home.MainActivity |
| Recents | com.hnlens.launcher3/com.android.quickstep.RecentsActivity |
| 재현율 | 확률적(타이밍 의존). 스트레스 시 ANR 변종 ~1/5 관측 사례 |

## 2. 증상

- 최근앱에서 "모두 닫기"(すべて閉じる) 탭 후 홈이 검은/빈 화면.
- 변종: com.hnlens.simplemode 입력 타임아웃 ANR (focused-but-invisible 홈).

## 3. 재현 조건 · 트리거 타이밍

- 앱 여러 개 실행 → APP_SWITCH → 모두 닫기. 취약 윈도우: 닫기 전환 중
  50~150ms 에 APP_SWITCH 재진입.
- ANR 변종: recents↔home 고속 반복 + 모두닫기 + HOME 복귀가
  SurfaceFlinger 합성 정지(3~5s)와 겹칠 때.
- 런처 키 차단창(eventInBlockTime ~500ms) 존재 → 키 전 0.6s 정지 필요.

## 4. 판정 시그니처

### FAIL
| 신호 | 소스 | 귀속 방법 |
|---|---|---|
| display-0 mCurrentFocus=null 지속 | dumpsys window | awk 로 display 0 블록만 + 0.5s 지속성 게이트 |
| 모두닫기 후 빈 RecentsActivity 전면 잔류 | dumpsys activity | display-0 resumed 확인 |
| ANR | logcat | `ANR in / Input dispatching timed out / does not have a focused window` |
| 복구 HOME 후 빈 화면 | 스크린샷 stddev | 복구 시나리오 한정 FAIL 격상 |

| slow_recovery / blank_pixels / recents_not_shown / clear_all_not_found | artifacts 수동 검토 |

### 알려진 오탐 (FAIL 금지)
- `Changing focus ... to null displayId=0` — 정상 전환 churn (6회/회차 수준)
- 서브 디스플레이(display 2)의 mCurrentFocus=null — 항상 null
- 복구 시나리오에서 빈 최근앱("最近のアイテムはありません") — 정상
