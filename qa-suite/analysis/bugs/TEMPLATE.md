# BUG-XXXXX: <트래커 제목 그대로>

> 작성: <이름/도구> / <날짜>
> 상태: 분석중 | 구현가능 | 구현완료 | 보류(미해결 질문 있음)

## 1. 메타

| 항목 | 값 |
|---|---|
| 트래커 ID / 링크 | |
| 대상 단말 / 모델 | 예: AT-M140 (THOR2-J) |
| OS / 빌드 | 예: Android 14, UP1A.231005.007 |
| 빌드 타입 | user / userdebug  ← 권한 제약 판단 기준 |
| 발생 모드/조건 | 예: Simple mode, 듀얼 디스플레이(main=0) |
| 재현율(알려진) | 예: 확률적, ~1/20 |

## 2. 증상 (관찰된 그대로)

- 사용자/리포터가 본 현상을 단정 없이 기술.
- 스크린샷·로그가 있으면 경로/첨부 표기.

## 3. 재현 조건 · 트리거 타이밍

- 선행 상태(어떤 앱이 떠 있어야 하는지 등)
- 트리거 동작 시퀀스 (키/탭/타이밍 윈도우를 ms 단위까지)
- 타이밍이 핵심이면 "취약 윈도우" 명시. 예: 모두닫기 전환 중 50~150ms

## 4. 판정 시그니처  ★ 구현 차단 항목 — 비어 있으면 구현 금지

### FAIL (확정 신호 — 반드시 프로세스 귀속)
| 신호 | 소스 | 귀속 방법 |
|---|---|---|
| 예: `Input dispatching timed out` | logcat | 대상 pkg 라인만, 또는 am_anr 이벤트 |
| 예: display-0 `mCurrentFocus=null` 지속 | dumpsys window | display 블록 스코핑 + 지속성 게이트 |

### WARN (의심 — 사람이 아티팩트로 확정)
| 신호 | 비고 |
|---|---|
| 예: blank 픽셀(stddev<0.02) | 스크린샷 수동 검토 |

### 알려진 오탐 (절대 FAIL 로 쓰지 말 것)
- 예: `Changing focus ... to null` — 정상 전환 churn

## 5. 권한 · 환경 제약 (user 빌드 기준)

- 필요한 adb 동작과 user 빌드 가능 여부:
  - [ ] 예: 타 uid kill -9 → 불가, am force-stop 대체 (시맨틱 차이: ___)
- 대체 수단이 재현 시맨틱을 바꾸는지: 예 / 아니오 / 검증 필요

## 6. 합격 기준

- 예: N=100 반복 FAIL 0 + WARN 수동검토 통과, 연속 2~3 빌드 재검

## 7. 자동화 판단

- 자동화 가능 범위 / 수동 병행 필요 항목
- 기존 하니스 재사용 여부 (있으면 래핑, 재작성 금지)

## 8. 미해결 질문  ★ 비어 있지 않으면 상태=보류

- 예: force-stop 으로 persistent 급사 타이밍이 동일 재현되는가?

## 9. 아티팩트 요구

- FAIL/WARN 시 수집 목록 (기본: screen.png, window.txt, activities.txt,
  logcat_tail.txt, context.txt + 버그 특이 항목)
