# BUG-24570: Gmail crash (DeadObjectException) after GMS persistent kill → Setup Wizard

> 작성: QA(정) 초안 / 2026-06-11
> 상태: 보류(미해결 질문 있음) — 8장 해소 전 모듈 구현 금지

## 1. 메타

| 항목 | 값 |
|---|---|
| 대상 단말 | (기입) |
| OS / 빌드 | (기입) |
| 빌드 타입 | user ← kill -9 / MASTER_CLEAR 불가 전제 |
| 재현율 | (기입) |

## 2. 증상

- GMS persistent 강제 종료 직후 Setup Wizard 재진입 시 Gmail 이
  DeadObjectException 으로 crash 한다고 보고됨.

## 3. 재현 조건 · 트리거 타이밍

- GMS persistent 종료 → 수 초 내 Setup Wizard 진입 → Gmail 의
  ContentProvider 접근 타이밍에 crash 추정. (정확한 윈도우 미확인)

## 4. 판정 시그니처

### FAIL (프로세스 귀속 필수)
| 신호 | 소스 | 귀속 방법 |
|---|---|---|
| Gmail crash | logcat | `FATAL EXCEPTION` 블록 내 `Process: com.google.android.gm` 동시 확인 |
| 또는 am_crash | events 버퍼 | `logcat -b events -d \| grep am_crash` 에서 com.google.android.gm 라인 |

### 알려진 오탐 (FAIL 금지)
- 광역 `DeadObjectException` grep — 시스템 전반에서 흔함. 단독 사용 금지.

## 5. 권한 · 환경 제약 (user 빌드)

- [불가] 타 uid `kill -9` → 대체: `am force-stop com.google.android.gms`
  (shell 가능. 단, persistent "급사"와 종료 시맨틱 다름 — 8장 Q1)
- [불가] `MASTER_CLEAR` broadcast (factory reset) → 재현에 필수인지 자체 불명 — Q2
- [검증 필요] 프로비저닝 완료 단말에서 `am start` 로 Setup Wizard 정상 재진입 여부 — Q3

## 8. 미해결 질문 ★

- Q1: force-stop 으로 persistent 급사 타이밍이 동일하게 재현되는가?
      (수동 1회: force-stop 직후 SUW 진입으로 crash 재현되는지 확인)
- Q2: factory reset 이 재현 조건에 실제로 필요한가? 트래커 원문 재확인.
- Q3: SUW 재진입 경로 — am start 가 막히면 어떤 진입 방법을 쓰는가?
