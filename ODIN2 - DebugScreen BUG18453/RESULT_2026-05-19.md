## 상세

### T1 — bootup internet IP / IMS IP (runtime PASS, 전제조건 주의)
- 재부팅 확인(boot_id 변경). 부팅 직후 `mobile_data setting=0` → internet PDN 미기동.
- 데이터 ON 후: internet.lguplus.co.kr → rmnet_data3 10.47.201.122 CONNECTED, IMS → rmnet_data2 2001:4430:e9:1d83:3c:d1ff:fef3:f38 CONNECTED.
- DebugScreen: IP=10.47.201.122, IMS IP=2001:4430:e9:1d83:3c:d1ff:fef3:f38 — ground-truth 일치.

### T2 — tethering IP 표시 (WIFI + USB 모두 검증)
- WIFI(root start-softap, 03): DUN `tethering.lguplus.co.kr` CONNECTED, rmnet_data4 10.22.192.101 → DebugScreen DUN IP=10.22.192.101 일치.
- WIFI(단말 UI, 09): rmnet_data4 10.22.195.132 → DebugScreen DUN IP=10.22.195.132 일치.
- USB(단말 UI, 07): DUN CONNECTED rmnet_data1 10.22.192.93, tethering upstream=rmnet_data1 → DebugScreen DUN IP=10.22.192.93 일치.
- 결론: WIFI/USB·root/UI 무관, tethering 활성 시 DUN PDN IP가 `DUN IP:` 필드에 표시됨. 원본 버그(hotspot IP 미표시) 대비 표시로 개선.

### T3 — "DUN" 문구 미표시 (BUG-GAP)
- DebugScreen에 "DUN IP:" 라벨이 tethering 활성/비활성, WIFI/USB 모두 상시 표시 (베이스라인 01에서도 라벨 존재, 값만 빈칸).
- 지시 #3 "DUN 이라는 문구가 미 표시" 와 상충.
- 스펙 모호: 지시 #2(tethering IP 표시)와 #3(DUN 문구 제거)이 양립하려면 "tethering IP를 일반 IP 필드에 표시 + DUN 라벨 제거" 설계여야 함. 현 Z0518U는 tethering IP를 "DUN IP:" 필드에 표시. 최종 설계 의도는 보고자(Sh hwang)/개발(YanLijie) 확인 필요 — 본 검증은 사실만 기록, 판정 보류.

### T4 — tethering 해제 시 IP 미표시 (WIFI=지연 clear, USB=즉시 clear)
정정 이력: 초기 "WIFI=BUG-GAP(영구 stale)"로 단정 → 라이브 재검증에서 ~2분 후 clear 확인되어 "지연 clear"로 정정.

- **WIFI 핫스팟 OFF = clear 지연**:
  - 네트워크 계층은 즉시 완전 teardown(rmnet 제거, `Current upstream: null`, telephony CONNECTED 부재) — root `stop-softap`·단말 UI 양쪽 동일.
  - DebugScreen DUN IP: 해제 후 **~38–45s 까지 직전 IP 잔존**(04/05/06/10/11), **~2분23초 시점엔 빈칸 clear**(라이브 12, 18:02:35 OFF → 18:04:58 캡처 + 테스터 육안 PASS).
  - 즉 영구 stale 아님. clear 되긴 하나 즉시가 아니라 수십 초~약 2분 지연. 정확 latency·갱신 트리거(타이머/이벤트)는 미측정.
  - 초기 BUG-GAP 단정 원인 = 자동 검증이 teardown 후 ~38–45s 라는 너무 이른 시점만 확인.
- **USB 테더링 OFF = 즉시 clear (PASS)**:
  - 단말 UI 토글 OFF(08) 시 ~18s 내 DebugScreen DUN IP 빈 값.
- 비대칭(약화): 동일 DUN PDN이 WIFI 해제 시 clear 지연(~수십초+), USB 해제 시 즉시. 표시 갱신 라우팅이 downstream 종류에 의존 의심 — root cause는 System/Telephony 오너 영역. 사용자 체감상 WIFI 해제 직후 잠시 잔존 표시되는 점은 보고 가치 있음(영구 결함은 아님).
