## E-02 · Debug Screen 필드 목록 상충

**구분** 규격 상충
**위치** 기술요구서 `7.13.1` ↔ 시험절차서 `19.1.2 판정1`

E-01의 참조를 7.13.1로 정정하더라도, 두 목록의 내용 자체가 일치하지 않는다.

### 대조 결과

| 항목 | 기술요구서 7.13.1 | 시험절차서 19.1.2 판정1 | 판정 |
|---|---|---|---|
| Cell ID 정의 | NCI 내 **36bit**의 Cell Identity 값을 decimal로 표현 | NCI의 **LSB 14bit**를 decimal로 표현 | **상충** |
| Vendor ID | — 미기재 | NCI의 MSB 2bit를 decimal로 표현 | **절차서에만 존재** |
| gNB ID | — 미기재 | NCI (22bit)를 decimal로 표현 | **절차서에만 존재** |
| SSB RSRP 범위 | SSB Index/RSRP : PSCell의 **Serving** SSB Index와 RSRP | SSB index 별 RSRP : PSCell의 **모든** SSB RSRP | **상충** |
| TA (Timing Advance) | 포함 | — 미기재 | **요구서에만 존재** |

그 외 28개 필드(5GMM State/Cause, 5GSM State/Cause, DRX cycle, IMS status, UpperLayerIndication, RestrictDCNR, Dual Connectivity status, DL/UL NR-ARFCN, Band, Bandwidth, PCI, SRB3, CSI-RS RSRP, RSSI, SSB SINR, CSI-RS SINR, Tx Pwr, ENDC Total Tx Power, CQI/RI, Best Neighbor Cell, Scell Status, RLF Cause, SCG Failure Cause, Temperature control, Tput All DL/UL, Tput DL, Tput UL)는 양 문서 일치.

### 문제

1. **NCI 분해 방식이 다르다.** 요구서는 NCI를 단일 `Cell ID` 필드(36bit)로 두고, 절차서는 `Vendor ID`(MSB 2bit) / `gNB ID`(22bit) / `cell ID`(LSB 14bit) 3필드로 분해해 요구한다. 요구서대로 구현하면 절차서 판정에서 3필드 중 2필드 누락으로 FAIL, 절차서대로 구현하면 요구서 기준 Cell ID 정의 불일치가 된다.
2. **TA 필드**는 요구서만 요구하므로, 절차서 판정만 통과시키면 요구서 미충족이 된다.
3. **SSB RSRP 표시 범위**가 Serving 1개인지 전체인지에 따라 화면 구성과 판정이 달라진다.

### 정정 요청

두 목록 중 어느 쪽이 정본인지 확정 후 타방을 동기화. 특히 아래 3점의 확정이 필요하다.

- Cell ID = NCI 36bit 단일 필드 / Vendor·gNB·cell 3필드 분해 중 어느 쪽인가
- TA(Timing Advance) 표시 필수 여부
- SSB RSRP를 Serving만 표시하는가, 수신 가능한 전체 SSB를 표시하는가

## E-06 · 판정기준 내용 모순

**구분** 판정기준 모순
**위치** 시험절차서 4.3 / 4.4 / 4.1↔4.5 / 11.5

리넘버링과 무관한 **내용 오류**다. 판정기준을 그대로 적용하면 절차와 반대되는 결과를 요구하게 된다.

### (1) 4.3 판정4 — 전환 방향이 반대

> 판정4 SIM 포트2 회선이 다음의 절차를 모두 완료하여 **SIM 포트1 회선으로 자동 전환**되는지 확인한다.

4.3은 **포트1을 비활성화**한 뒤 포트2가 모바일 데이터를 넘겨받는 흐름이다. 비활성화한 포트1로 전환된다는 서술은 방향이 맞지 않는다. `포트2 회선으로`의 오기로 보인다.

### (2) 4.4 판정2 — 포트 번호가 시험방법과 불일치

> 판정2 SIM 포트2 회선이 다음의 절차를 모두 완료하는지 확인하고, 다른 디바이스에서 **SIM 포트1 회선**의 번호로 발신하여 '전원 OFF' 안내를 받는지 확인한다.

4.4는 **포트2를 비활성화**하는 시험이므로 '전원 OFF'가 되어야 하는 쪽은 포트2다. 같은 항목의 시험방법 7)은 "**SIM 포트2 회선**의 번호로 발신"이라고 기술해 판정기준과 어긋난다.

### (3) 4.1 ↔ 4.5 — 동일 동작에 다른 대기 기준

| 위치 | 기재 |
|---|---|
| 4.1 판정2 | "IMS Registration 완료 후 **X초** 뒤 … ※ timer X는 당사 프로토콜 담당자와 사전 협의된 값을 사용해야 한다" |
| 4.5 판정3 | "IMS Registration 완료 후 **5초** 뒤" |

두 항목이 같은 동작(포트2의 IMS Registration 완료 후 RRC Idle 천이)에 서로 다른 기준을 제시한다. 4.1은 값을 협의 대상으로 두고 4.5는 5초로 고정했다.

### (4) 11.5 — 전제 자체가 성립하지 않음

11.5는 시험방법 1)에서 "**WCDMA 신호만 있는 시험 환경을 구성한다. (LTE 신호 없음)**"을 요구한다. 그런데 4)·5)는 SIM 조건을 이렇게 기술한다.

> 4) 디바이스에 미개통 SIM(**EMM cause #8 포함 Attach reject 메시지 수신**)을 장착하여 **EMM 'Attach' 절차에 실패**하는지 확인하고
> 5) 디바이스에 가입 해지된 SIM(**MAC failure에 의한 Authentication reject 메시지 수신**)을 장착하여 **EMM 'Attach' 절차에 실패**하는지 확인하고

LTE 신호가 없으면 EMM Attach 자체가 발생하지 않으므로 "EMM Attach 실패 확인"이 불가능하다. SIM의 **성질을 설명하는 부기**로 읽어야 하는지, 실제 확인 절차로 읽어야 하는지 확정이 필요하다.

### 정정 요청

- 4.3 판정4 — `SIM 포트1 회선으로` → `SIM 포트2 회선으로`
- 4.4 판정2 — `SIM 포트1 회선의 번호로` → `SIM 포트2 회선의 번호로`
- 4.1 판정2 ↔ 4.5 판정3 — 대기 기준 단일화 (협의값 / 5초 중 정본 확정)
- 11.5 4)·5) — LTE 부재 환경에서 EMM Attach 확인이 절차인지 SIM 성질 부기인지 명확화
