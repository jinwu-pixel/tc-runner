# 개발 문의 — THOR2_J 접근성 연결 후 다이얼러 하드 `*` 입력 소실

작성일: 2026-07-13
대상: AT-M140 / Android 14 / `com.android.dialer` 1.0.0 (build 1638) / iWnn 2.23.1 (build 10)
관련 이슈: `IME-CALL-001` (`CONFIRMED`, `OPEN`)

## 1줄 요약

접근성 또는 UiAutomation 연결이 한 번 발생한 뒤 iWnn이 활성화된 다이얼러에서 물리 키패드의 `*`만 입력되지 않습니다. 동일 물리 프레스는 커널까지 정상 도달하며, 재부팅 전까지 증상이 유지됩니다.

## 사용자 영향

AT-M140은 물리 키패드 사용 비중이 높은 단말입니다. TalkBack 사용자는 접근성 연결이 상시 활성화되므로 `*141#` 같은 `*`/`#` 기반 발신 코드를 물리키로 입력하지 못할 수 있습니다. 숫자와 `#`는 같은 조건에서 정상 입력됩니다.

## 기대 결과와 실제 결과

| 조건 | 물리키 입력 | 기대 | 현재 실제 |
|---|---|---|---|
| 재부팅 후, 접근성/자동화 연결 이력 없음 | `3*#` | `3*#` | `3*#` |
| UiAutomation 연결 1회 후 | `3*#` | `3*#` | `3#` |
| 위 상태에서 다이얼러 재실행 | `3*#` | `3*#` | `3#` (재부팅 전까지 유지) |

## 최소 재현 절차

> 필드 판정은 육안으로 수행합니다. 입력 뒤 `uiautomator dump`, Appium, TalkBack 이벤트 판독을 사용하면 관측 행위가 트리거 조건과 섞이므로 금지합니다.

1. iWnn을 기본 IME로 둔 상태에서 단말을 재부팅합니다.
2. 부팅 후 접근성 서비스, UiAutomator, Appium을 연결하지 않습니다.
3. 물리키로 다이얼러를 열고 `3*#`를 입력합니다.
   - 기준선: 번호 필드에 `3*#`가 표시됩니다.
4. 필드를 비우고 다이얼러를 종료합니다.
5. 호스트에서 UiAutomation 연결을 정확히 한 번 발생시킵니다.

   ```sh
   adb -s <serial> shell uiautomator dump /sdcard/ime_call_trigger.xml
   ```

6. 물리키로 다이얼러를 다시 열고 `3*#`를 입력합니다.
   - 기대: `3*#`
   - 현재 실제: `3#` (`*` 소실)
7. 다이얼러만 재실행하여 6을 반복하면 동일 증상이 유지됩니다. 재부팅하면 기준선으로 복귀합니다.

## 확인된 경계

- 3개 AT-M140 유닛에서 교차 확인했습니다.
- 물리 `*` 프레스는 `getevent`에서 `KEY_NUMERIC_STAR` DOWN/UP 1쌍으로 정상 관측됩니다.
- `adb shell input keyevent`의 가상 입력에서는 재현되지 않습니다. 물리 키패드 경로에 한정됩니다.
- iWnn 비활성 조건에서는 물리 `*`가 정상 입력됩니다.
- 트리거는 재현 가능한 black-box 인과로 확인했지만, 최종 코드 결함의 소유 지점이 다이얼러 입력 처리인지 iWnn 하드키 처리인지는 소스 확인이 필요합니다.

## 개발 확인 요청

1. 접근성/UiAutomation 연결 후 `TYPE_CLASS_PHONE` 계열 입력 필드에서 iWnn이 물리 `KEYCODE_STAR`를 기능키로 소비하는 경로가 있는지 확인해 주세요.
2. `com.android.dialer` 번호 필드가 물리 `*`를 IME에 위임하거나 직접 처리하는 조건이 접근성 연결 전후로 달라지는지 확인해 주세요.
3. 접근성 연결 유무와 관계없이 물리 `*`가 번호 필드에 그대로 전달되도록 수정 가능한지 검토해 주세요.
4. 수정 빌드에서는 `TC_IME_CALL_001_A11Y_STAR_REGRESSION.yaml`의 최소쌍을 수행해, 연결 전후 모두 `3*#`가 입력되는지 확인해 주세요.
