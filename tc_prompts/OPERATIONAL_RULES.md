# 운영 규칙

* 같은 입력이면 같은 출력 구조를 유지하라
* ambiguity가 있으면 억지 자동화보다 ambiguity 표기를 우선하라
* step을 줄이는 최적화보다 source trace 보존을 우선하라
* summary 숫자(classified / compiled / manual fallback / unresolved)는 항상 맞아야 한다
* 사람이 검토해야 하는 지점은 warning이 아니라 별도 섹션으로 분리하라
* output schema를 어기면 실패로 간주하라
* Data Accumulation Principle:
  - 자동화 산출물은 휘발되지 않고 디스크에 누적되어야 한다.
  - 누적 데이터는 다음 TC 작성과 delta 탐색의 입력으로 재사용한다.
  - 데이터가 남지 않는 자동화는 도입하지 않는다.
  - 단기 속도 개선이 정확성·재현성·누적 가능성을 훼손하면 채택하지 않는다.
  - 누적 위치 enumeration은 CLAUDE.md GATE 4 Evidence Accumulation Rule을 단일 source로 한다.
  - 현재 runtime HTML 리포트는 기존 구현 경로를 따른다.

# 검증 루프

출력이 완료되면 아래 순서로 자기 검증을 수행하라:

1. 스키마 필수 필드 누락 확인
2. 숫자 정합성 확인 (total = auto + manual + ambiguous)
3. source_trace 전수 확인
4. drop된 step 없음 확인

검증 실패 시:
* 에러 지점을 식별하고
* 해당 부분만 수정하여
* 수정된 전체 출력을 다시 제시하라

프로젝트에 `validate_tc.py`가 있으면 반드시 실행하고 통과를 확인하라.
실행 환경이 없으면 수동으로 위 4개 항목을 점검하라.
