## TC01 — 등록 override 복합 (Domain·PRID·RegExp·UA·SubExp·SIP Timer)

**TC01 입력값 (3사 동일, 사용자 확인 2026-06-23)**: Domain=`sktelecom2`(bare realm, 비-routable) · User Agent=`ALT-test` · PRID=`4500612345678@ims.mnc006.mcc450.3gppnetwork.org` · Register Expires=`1200` · Subscribe Expires=`5000` · SIP Timer T1=`1000`. (입력 가이드도 "bare realm sktelecom2 → 404(TC1)" 명기 — 의도된 negative.)

**SKT (on-wire, 권위)** — 캡처 12:32:55~12:57:27 KST:
- REGISTER 19/19 동일: req-URI `sip:sktelecom2` · `Expires:1200` · `User-Agent:ALT-test` · `Authorization … username="4500612345678@ims.mnc006.mcc450.3gppnetwork.org", realm="sktelecom2"` → 전부 **404 NOT FOUND `cause=4006 ORIG USER NOT HOME`**.
- **자동 대조(`ims_sip_digest.py --expected`) = 5/5 PASS** (req-URI·Expires·UA·Auth username·realm 전부 입력값 일치).
- Way1 reboot-load: 6필드 reboot 후 modem readback 일치(영속+로드). SubExp(5000)·SIP Timer T1(1000)은 404 즉시거부로 SUBSCRIBE/재전송 미발생 → **구조적 미관측(NOTE)**.
- 판정: **입력 6필드가 등록에 그대로 반영됨(`manual evidence observed`)**, 404는 비-routable override 도메인의 **설계된 결과**(BUG 아님).

**LGU+ (QShrink)** — 15:33:25 `REGISTERED`(60ms) → `NOT_REGISTERED ec400 errorMessage="Bad Request()"`. → **등록 거부(400) 관찰** = 동일 bogus 도메인 override의 결과로 정합(SKT 404와 다른 실패 모드). 단 req-URI는 offline QShrink에 미기록 → override-적용 자체는 on-wire 미확인. 진단 `OBSERVED`.

**KT (QShrink)** — 16:21:45 `REGISTERING→REGISTERED`(부팅 ~8s 후), 망 거부 0, 종료 16:24:11 `NOT_REGISTERED ec999`(teardown) → **등록 성공**. 단 QShrink는 req-URI를 안 남겨 **override(sktelecom2)가 이 등록에 실제 로드됐는지 확인 불가** = **inconclusive**(캡처가 override-reboot 前 default 등록일 가능성 / KT가 bogus 도메인 허용 가능성 — offline로 구분 불가).

> **TC01 정리**: 입력 3사 동일(sktelecom2). **SKT = override 등록 깸(404, on-wire 확정)** · **LGU+ = 등록 거부(400) 관찰** · **KT = 등록 성공이나 override-load offline 미확인(inconclusive)**. KT/LGU+ on-wire(req-URI) 확정은 **QXDM 재캡처**만 가능.

## TC02 — 호 override 복합 (Voice/Session/RTP/Video/Port)

**SKT (on-wire INVITE, 권위)** — 영상호 4회(10:59:20~11:00:32 KST), 전부 200 OK 연결:
- `Session-Expires: 50000;refresher=uac` (기본 1800 → **override 반영**)
- `m=audio 50002/50008/50006/50010` = **Traffic Port override**(50000대)
- AMR-WB(104,103) **선두** + AMR-WB/16000 존재 = **Voice Codec priority + HD Voice ON 반영**
- `m=video … H265` 720×1280@24 우선 + H263 fallback = **Video Codec H.265 반영**
- **ModeSet 반영(PASS, 정정)**: 입력 비트마스크 `0x04(M2)`/`0x08(M3)` → on-wire fmtp `mode-set=2`/`3` (입력가이드 매핑 일치).
- **Traffic Port (사용자 확인 2026-06-23: speech 50000/50010만 설정, video 미설정)**: on-wire `m=audio 50002·50006·50008·50010` 전부 speech 범위(50000–50010) 내 = **speech 포트 반영(PASS)**. `m=video 7020`(=SKT default)은 video 포트 override **미설정**이므로 **정상**(반영할 값 없음) → 이전 ⚠ 해소.
- 판정: call-복합 override **전부 on-wire 반영(`manual evidence observed`)** — SE·refresher·speech port·voice codec·HD·ModeSet·video codec 모두 입력대로, **mismatch 0**.
