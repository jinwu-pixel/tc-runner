## ★ BUG-GAP 후보 — IMS Reset 후 Write 무반영 (진단 `OBSERVED`)

> ⚠ **정정 (2026-06-16 오프라인 재검증, ↓Phase 3)**: 아래 "Write 무반영(silent no-op)" 관찰은 정정됨 — post-reset write는 런타임 커밋되며, 실제 성격은 reset 후 1회 reboot로 환원되는 **비영속**. 결론은 Phase 3 참조.

C2 reset 직후 관찰된 거동을 진단:

| 검사 | 입력 | Write status | 실제 Read 값 |
|---|---|---|---|
| AMR ModeSet=240 | `et_detail_input=240` (입력 확인됨) | **OK** | `(not configured, default 0)` (무변경) |
| RTP=12 | `et_detail_input=12` (입력 확인됨) | **OK** | `(not configured)` (무변경) |
| settle 재read RTP/Session | — | — | `(not configured)` 지속(transient 아님) |

- **현상**: 글로벌 IMS Reset(`deactivateConfigs`+`enableAutoMode`) 직후 단말이 auto/deactivated 상태 → 엔지니어 Write가 **status "OK" 표시하면서 실제 미반영**, Read는 `(not configured)`.
- **대조**: reset 전에는 동일 Write가 정상 적용(C2 Step1/2 RTP=15·Session=1810 stuck). reset 안 한 RTP는 reset 후 `10`(C1). → **명시 Write를 한 NV가 글로벌 reset 후 `(not configured)`로 떨어지고 재Write 무반영**.
- **연결**: BTS #25049 노트 "reset 버튼이 default 복원 대신 config 삭제(→수정됨)"와 동종 현상. #19581 history "reset → default 10이어야" 관심사와 닿음.
- **가설(미확정)**: (a) auto mode가 수동 override 무시 = 설계상, (b) reboot 전 config 재활성 안 됨, (c) Write 실패인데 "OK" 오표기. **discriminator = reboot 후 거동** (reboot 시 RTP=10 복귀 + Write 재작동 여부).
- **NOTE**: readback-only 한계 — Write 실패인지 Read 마스킹인지 단정 불가. reboot로 판별 필요.
- **현 단말 상태**: RTP/Session/AMR = `(not configured)`, 엔지니어 Write 무반응. C3(AMR 격리) 본검증은 이 상태 해소(reboot) 후 가능.

증거: `evidence/device/c2_*.png`, `c3_amrwb_*`, `diag_amr_input.png`.

|---|---|---|
| RTP Timer | (not configured) | **10** |
| Session Expires | (not configured) | **1800** |

# Phase 3 — 오프라인로깅 재검증 (RESET-NONPERSIST 정정)

방법: 단말 내장 offline diag + 영상 녹화 하 readback(Way1 UI / Way2 모뎀 로그). join = boot_id + KST. 상세 타임라인 = `evidence/device/offline_session_ledger.md`.

| Phase | 시나리오 | 결과 |
|---|---|---|
| B | IMS Reset → write → reboot | post-reset write 커밋(RTP15·RegExp36000 readback 일치) → reboot 후 환원(RTP10·not configured) |
| C | (control) reset 없이 RTP write → reboot | RTP 15 **영속** |
| D | (control) reset 없이 EFS RegExp write → reboot | RegExp 36000 **영속** |

**정정 결론**: 원 §BUG-GAP "Write status OK인데 무반영(silent no-op)"은 **불성립** — write는 NV `writeNvField result=0`·EFS `[INI_WRITE] result=0` + 자동 readback 일치로 **런타임 커밋**됨. 실제 = **reset-induced persistence loss**: IMS Reset의 `enableAutoMode=true`가 config를 auto로 둬 직후 1회 부팅의 MBN reload가 override를 덮음. control(C/D)이 reset 없는 write의 reboot 영속을 보여 **비영속=reset 특이**임을 직접 확정. 진단 `OBSERVED`(n=1·SKT·`.qmdl` 미생성). 원 pre-reboot "무반영" 관찰은 입력 아티팩트(EditText·focus 레이스) 추정.
