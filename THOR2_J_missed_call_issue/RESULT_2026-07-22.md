## 1. 자동 읽음 트리거 매트릭스 — 수정 전 라인 (단말 B)

실 부재중 3건(`is_read=0`) + NULL 더미 1건(`990501`) = 미확인 4 상태에서 측정.

| 조작 | 자동 읽음 | 미확인 | 근거 |
|---|---|---|---|
| Recent 탭 **진입만** | ✗ | 4 유지 | `K1` |
| Recent → **다른 탭 전환** | **O 전건** | 4 → **0** | `K4` |
| Recent → **홈 이탈** | ✗ | 유지 | `K2` · `K6`·`K7` (2회, 화면 표시 확인 포함) |

**★ 사용자 요청문의 "다른 탭으로 이동하거나 홈화면으로 나오면" 중 홈 이탈은 수정 전 빌드에도 없던 동작이다.**
→ '과거 동작 복원'이 아니라 신규 추가. 요청 시 명시 필요.

**부수 관찰**
- 처리 방식: `is_read`만 1로 변경, `new`는 1 유지 (두 컬럼 분리 취급)
- **NULL 행도 대상에 포함**됨 (`990501` → `is_read=1`)
- 간편 모드 미러 카운터도 NULL 포함 계수 (실 3 + NULL 1 = **4**)
- 실 수신 통화(`type=1`)는 `is_read=NULL`로 기록됨 — `is_read`는 부재중에만 의미를 갖는 것으로 보임

## 2. 굵게 표시 기준

| 표시 요소 | 기준 | 확인 |
|---|---|---|
| **굵기(bold)** | `is_read` — 미확인이면 굵게 | 동일 프레임 내 대조 3회 (`K1`·`K7`, 07-21 `F8`·`F11`) |
| 빨간 부재중 화살표 | `type` — 부재중이면 항상 | 읽음 처리 후에도 유지 |

**★ 수정 전 빌드에서도 자동 읽음 처리 후 굵기가 사라졌다** (`K1` → `K5`). 즉 「읽음 처리 후에도 굵게 유지」는
이전 동작의 복원이 아니라 **신규 기능**이다. 이전 버전에서 부재중 사후 식별은 **빨간 화살표만으로** 이뤄졌다.

`K7` 프레임이 가장 명확한 대조다 — `990-501`(`is_read=1`)만 비굵게, 나머지(`is_read=0`) 굵게, 배지 3.

## 3. 동일번호 그룹 시나리오 (#24947 3단계)

**조건**: 부재중 1건(`is_read=0`) + 직후 같은 번호 통화 연결 1건 → 콜로그에 1개 그룹으로 표시

| 항목 | 단말 B `RY07260601S` | 단말 A `SELJY072606DZ0721` |
|---|---|---|
| 배지 | 1 | 1 |
| 그룹 행 표시 | **비굵게** + 수신 화살표 → **식별 불가** | **굵게** → 식별 가능 |
| 그룹 행 탭 | 읽음 처리 **안 됨** | **미확인 0 + 알림 0 + 배지 소멸** |
| 통화 세부정보 진입 | 읽음 처리 안 됨 | — (탭에서 해소) |
| 근거 | `L1`·`L2`·`L3` (prev) | `M1`·`M2`(합성) · `N1`·`N2`(실 착신) |

**결론**: 「배지는 1인데 콜로그에서 부재중을 찾을 수 없다」는 증상은 **수정 전 라인의 증상**이며
**수정 후 빌드에서는 재현되지 않는다.** #24947 3단계에 해당하는 증상으로 판단된다.

- **검증 신뢰도**: 합성 데이터(`content insert`)와 **실 착신** 두 경로에서 동일 결과 확인
- 부재중 알림은 같은 번호의 통화 연결로 **자동 취소되지 않았다** (단말 A 확인)

## 5. 결정 사항 (요청 문안에 반영)

1. **일괄 읽음 요청은 #26174 수정을 되돌리는 것이 아니라 조건을 얹는 형태**로 작성 — "Recent 화면을 실제로
   확인한 경우에만". 단, 앱이 Recent 탭으로 자동 복원되어 열린 경우도 **열람으로 간주**(사용자 결정)
2. **굵게 표시 요청은 "회귀 방지"로 전환** — 단말 A에서 그룹 볼드 표시가 이미 정상 동작하므로,
   신규 요청이 아니라 3번 구현 시 변경되지 않도록 요청
3. **일괄 읽음 대상 술어를 문장으로 명시** — `is_read`가 NULL인 행 포함. 누락 시 #26510 재발
4. 홈·백그라운드 이탈 포함은 **신규 동작임을 명시**
5. **'모두 읽음' 메뉴 신설은 채택하지 않음** — 조사한 OEM 기본 전화 앱 중 해당 메뉴 보유 0건

최종 요청 문안(KO/EN)은 `bug_26510.xlsx` **개발자요청** 시트에 수록.
