# BUG #26510 재현 경로 (객관) — 부재중 배지 ↔ 콜로그 미확인 불일치 (노말모드)

- 단말: THOR2_J / AT-M140 / 빌드 `SELJY072606MZ0713` (Z0713U_J_MP). 이슈 본체 serial B2700125BW000115에서 divergence 라이브.
- 목적: 코드 수정이 아닌 **객관적·재현 가능한 경로 제공**. 분석 근거는 `RESULT_2026-07-13.md`, 증거는 `issue_2026-07-13_unit115/`.
- 어휘: 값·동작은 전부 실측(adb/logcat). 미확정은 `[개발팀 확인]` 표기.

## A. 버그의 객관적 정의 (측정 가능한 불변식)

노말모드 전화앱 배지와 콜로그(다이얼러 통화이력 탭)·심플모드 배지가 **서로 다른 소스**에서 값을 가져와 어긋난다.

| 표면 | 소스 (실측) | 측정 방법 |
|---|---|---|
| **노말 런처 배지** | 시스템 CallLog `is_read=0` 카운트 | `adb shell "content query --uri content://call_log/calls --projection _id --where \"type=3 AND is_read=0\""` → 행 수 |
| **다이얼러 통화이력 탭 배지 = 심플모드 배지** | hnlens 미러 "미확인" 카운트 | 다이얼러 Recent 탭 배지 시각 확인 / `adb logcat`의 `com.hnlens.simplemode: ... loadUnreadData unreadCallCount:` |

**버그 present 판정**: 위 두 값이 다르면 버그.
**현 이슈 단말 실측**: 시스템 `is_read=0` = **2** = 노말 배지 2 / 미러 = **54** / 다이얼러 Recent 탭 배지 = 54. → 2 ≠ 54, 버그 present.

---

## B. 의도된 동작 (확인 로직) — 사용자 확정

- 콜로그에서 미확인 부재중은 **볼드** 표시.
- **개별 항목 탭 → 읽음(확인) 처리** (볼드 해제). 확인 전까지 배지에 남아야 함.
- 따라서 **심플모드/미러(54)가 의도대로 동작 = 정답**. **노말 배지(2)가 미달 계수(under-count) = 버그.**

---

## C. 소스별 동작 (실측 근거)

1. **노말 런처 = 시스템 `is_read=0`**: adb로 `is_read` 토글 시 런처 배지가 ±1 정확 추종. 시스템 `content://call_log/calls`를 직접 쿼리.
2. **개별 탭 확인은 세 소스 동기**: 콜로그 070 항목 탭 → 시스템 `is_read` 0→1 + 런처 2→1 + 미러 54→53 (전부 −1).
3. **미러는 별개 store**: 시스템 `is_read=0`이 2인데 미러는 54. 미러가 관측한 `is_read` 변경은 ±1 추종하나, 시스템과 **항상 +52** 어긋남(라이브 매트릭스: 시스템 0/1/2 → 런처 0/1/2, 미러 52/53/54).
4. **`is_read` ≠ "확인" 신호**: 총 부재중 67 중 65가 `is_read=1`이지만 그중 52는 여전히 미확인(미러 기준). `is_read`는 개별 탭 외 경로로도 1이 됨.

5. **미러는 영속 누산기, 재시작 시 reconcile 안 함 (실측 확정)**: `com.hnlens.simplemode`를 force-stop 후 콜드 재시작(새 pid)해도 미러 = **54** 유지(시스템 `is_read=0`=2와 무관). → 미러는 부팅/재시작 시 시스템 CallLog로 전량 재동기하지 않고 **영속 테이블 값을 그대로 로드**. 이것이 52-gap이 **영구적**인 핵심 이유.
6. **알림 dismiss 단독은 트리거 아님 (실측 확정)**: 심플모드 실행 중 부재중 알림 스와이프 dismiss → 시스템 `is_read` 일괄 1 + **런처·미러 둘 다 −2**(미러가 관측·추종). 갭 불변. 즉 dismiss 자체는 divergence를 **만들지 않음**(미러가 실행 중이면).

→ **divergence 성립 조건 (실측 종합)**: 미확인 부재중의 **시스템 `is_read`가 1로 클리어되는 순간 미러가 관측하지 못하고**(프로세스 미실행/부팅 옵저버 미등록/옵저버 우회 일괄 UPDATE), **미러는 재시작해도 reconcile 안 하므로** 그 놓친 클리어가 영구 갭이 됨. 그 순간부터 노말(시스템 is_read)은 제외, 미러는 미확인으로 영구 유지 → 갭.

## D. 재현 절차

### D-1. 원 QA 경로 (#26510 등록 조건 — 그대로 기록)
1. 저장된 연락처로부터 부재중 전화 수신.
2. 해당 연락처 삭제.
3. 노말 배지 vs 콜로그 미확인 개수 비교 → 어긋남.

**비고(실측)**: 건강 단말에서 **연락처 삭제 단독으로는 미재현**(삭제 시 onChange 0·불일치 0). 삭제 자체보다, 삭제/조작이 유발하는 "미러 미관측 상태에서의 is_read 클리어"가 트리거. → D-2 조건이 근본.

### D-2. 메커니즘 기반 결정적 조건
divergence 필요조건 = **① 미확인 부재중 존재 → ② 그 부재중의 시스템 `is_read`가 1이 됨 → ③ ②의 순간 미러가 관측하지 못함**(미러는 재시작해도 reconcile 안 하므로 영구 갭).

**실측으로 확정된 경계**:
- 시스템 `is_read`를 개별 탭 없이 1로 만드는 경로 = 부재중 알림 dismiss(AOSP `CANCEL_ALL_MISSED_CALLS`, 스와이프 시 `is_read=1`+`new=0` 일괄) — **실측 확인**.
- 단, **미러 실행 중 dismiss는 미러가 −N 추종 → 갭 안 생김**(실측). 따라서 **dismiss 타이밍이 미러 미관측 구간과 겹쳐야** 갭 발생.
- **미러 미관측 구간** = 심플모드(`com.hnlens.simplemode`) 프로세스 미실행 구간(메모리 압박 kill·부팅 직후 옵저버 미등록·옵저버 우회 bulk UPDATE). 미러는 콜드 재시작에도 reconcile 안 함(실측) → 그 구간의 클리어는 영구 갭.

- **결정적 재현 후보 시퀀스**:
  1. 부재중 여러 건 수신(전부 미확인·볼드) — 노말=콜로그 동기 확인(E 체크포인트).
  2. **미러(심플모드)가 미관측인 구간을 만든다**: 재부팅, 또는 심플모드 프로세스 종료.
  3. **그 구간 안에서** 부재중 알림 dismiss(또는 시스템 is_read 일괄 클리어) 발생.
  4. 심플모드/부팅 복귀 후 노말 배지 vs 콜로그 비교 → **노말 < 콜로그**면 재현.
  - 가장 자연스러운 실사용 재현 = **미확인 부재중이 있는 상태에서 재부팅**(부팅 과정 중 미러 옵저버 미등록 구간에 부재중 알림/카운트가 클리어되면 갭). #26510 원 경로(연락처 삭제)도 삭제가 유발하는 CallLog 일괄 갱신이 이 구간과 겹칠 때 발현하는 것으로 추정.

`[개발팀 확인]`: 실사용에서 어느 이벤트가 "미러 미관측 구간의 is_read 클리어"를 일으키는지(재부팅 타이밍 / 26174 fix의 is_read 클리어 경로) — 위 시퀀스로 재현 후 특정.

### D-3. 갭 확대/축소 검증 (이미 실측 — 재현 판정 보조)
- 갭 축소(정상): 콜로그에서 볼드 항목 **개별 탭** → 노말·콜로그 동시 −1(갭 유지). 세 소스 동기 확인용.
- 갭 존재: 위 D 조건 후 노말과 콜로그 차이가 0 아님.

## E. 객관적 확인 체크포인트 (각 단계 실행)

```bash
S=<serial>
# ① 노말 배지 소스 (시스템 is_read=0 카운트)
adb -s $S shell "content query --uri content://call_log/calls --projection _id --where \"type=3 AND is_read=0\"" | grep -c "Row:"

# ② 미러(콜로그/심플) 소스 — onChange 유발 후 logcat
adb -s $S logcat -c
adb -s $S shell "content update --uri content://call_log/calls --bind is_read:i:0 --where \"_id=<현재 is_read=0인 _id>\""   # 값 무변경 no-op으로 onChange만
sleep 2
adb -s $S logcat -d | grep -E "getUnreadMissedCallCount:|loadUnreadData unreadCallCount"
#   Launcher ——— getUnreadMissedCallCount: N  = 노말 배지
#   com.hnlens.simplemode ... loadUnreadData unreadCallCount: M = 미러(콜로그/심플)
```
**N ≠ M 이면 버그 present.** 다이얼러 Recent 탭 배지·심플 홈 배지 = M, 노말 홈 배지 = N.

## F. 수정 방향 가이드 (참고 — 수정은 개발팀 영역)

"노말모드만 실패, 심플 정상"의 정확한 이유 = **노말 런처만 배지 소스로 시스템 `is_read`를 씀**. 심플·다이얼러 통화이력 탭은 미러("미확인")를 씀. 개별 탭 확인 경로는 이미 세 소스를 동기하므로, 오염원은 "개별 탭 외 경로의 `is_read` 클리어"다.

- **(A) 소스 통일 (권장)**: 노말 런처 `getUnreadMissedCallCount`를 심플/다이얼러와 **동일한 미러("미확인") 소스**로 전환. 시스템 `is_read` 쿼리 폐기.
  - 장점: 세 표면 단일 소스 → 재발 원천 차단. 의도(미확인 유지) 정합.
  - 범위: 런처 배지 로직 변경.
- **(B) `is_read` 오염 차단**: 시스템 `is_read`를 **개별 탭 확인 외 경로**(알림 dismiss 등)에서 클리어하지 않도록.
  - 장점: 시스템 CallLog 의미 정합(다른 컴포넌트도 신뢰 가능).
  - 범위: 어느 경로가 클리어하는지 특정 필요 — **BUG #26174 fix의 `is_read` 클리어 시점 검토가 유력 단서**.
- **부수 항목**: `MissedCallNotificationReceiver.updateBadgeCount ... success:false`(Telecom→런처 배지 push 실패, 양 단말 공통)는 별개 이슈이나, (A) 채택 시 이 push 경로 의존이 사라질 수 있음.
