## 1. 근본 원인 (측정 확정)

**부재중 배지 두 소스의 `is_read` NULL 처리가 다르고, 툴이 만든 부재중은 `is_read=NULL`이라 어긋난다.**

| 소스 | 쿼리(측정) | is_read=NULL 행 | 
|---|---|---|
| 노말 런처 배지 (`com.hnlens.launcher3`) | `type=3 AND is_read = 0` | **제외** → under-count |
| 미러 (`com.hnlens.simplemode`, 다이얼러 Recent 탭) | `is_read ≠ 1` (=0 또는 NULL) | **포함** |

- 실 착신 = `is_read=0` (양산 실기 확인). 두 소스 일치.
- **툴(Batchuserdata) 삽입 = `is_read=NULL`** (툴이 컬럼 미설정). 노말은 빼고 미러는 세어 → divergence.
- 원본 54 vs 2 = 툴 52건(NULL) + 실 2건(is_read=0): 노말 `is_read=0`=2, 미러 `is_read≠1`=54. 정확히 일치.

## 2. 실기 근거 (전부 측정 · 가역)

1. **NULL 삽입 → 어긋남**: 툴식 3건(is_read 미설정) 삽입 → is_read=NULL. 노말=5 / 미러=8. (`is_read=0 OR NULL`=8 일치.)
2. **정/역**: 그 3건에 `is_read=0` 세팅 → 노말 5→8, 미러 8, 수렴. NULL이 단독 원인 확정.
3. **배지 = is_read 쿼리, 알림 카운트 아님 (통제 판별)**: 활성 부재중 알림 **5개** 상황에서 알림 없는 실 행 하나 `is_read` 1→0 → 홈 배지 **1** 표시(스크린샷 `F_isread0_1_notif5.png`), logcat `missedCallNotificationCount=1`. 알림 기반이면 5여야 함 → **노말 배지 = `is_read=0` DB 카운트**.
4. **시각 확인**: 홈 전화 배지 vs 다이얼러 Recent 탭 배지 스크린샷(`A_home.png`·`C_dialer_main.png`) — 홈 0 / Recent 🔴5.
5. **클리어 거동**: 개별 항목 탭 = `is_read`=1(미러 −1, 지워짐). 목록 조회 = NULL 안 지워짐(bulk가 `is_read=0` 대상). → 원본 "54 고정"이 "NULL이라 조회로 clear 안 됨"으로 단순 설명(이전 "영속 store no-reconcile" 추론 불필요).
6. **빌드 무관**: MZ0710에서 재현 → **버전 회귀 아님**.

증거: `version_compare_2026-07-15/nullread_visible/` (스크린샷), 실기 logcat.

## 4. 개발자 분석 대조 (ZenTao #26510)

- **일치(결론)**: 실 착신=알림·DB 1:1 / DB 직삽입(툴)=불일치, **실 사용 무영향**. 고객이 "자동생성 소프트웨어 데이터"임을 직접 확인(PengLi 코멘트). **MR2 수정 권고**. repro=Z0713U_J_MP(MZ0713).
- **우리가 정밀화(메커니즘)**: 개발자는 노말 배지를 "알림 카운트"로 서술 → 실 데이터에선 알림수=is_read=0수라 효과 동일하나, **실측은 `is_read=0` 쿼리**(§2-3). 개발자 코멘트엔 SQL·`is_read`·mark-as-read 언급 전무.
- **정밀 fix 타깃 제안(문의 형식으로 전달)**: 노말 런처의 `is_read=0` → `is_read IS NOT 1`(또는 `COALESCE(is_read,0)=0`)로 미러와 정합.

## 5. 정정 이력

- **2026-07-13 RESULT/REPRO의 근본 원인 설명 supersede**: 방향("노말 under-count, 미러가 미확인 유지")은 유지되나, **원인을 "미러 미관측 구간의 is_read 클리어 + 미러 영속 no-reconcile"에서 "툴 삽입 is_read=NULL + 노말/미러 NULL 처리 불일치"로 정정**. 원본 단말 초기화로 옛 force-stop 실험은 재검증 불가 — NULL 설명이 더 단순·정합.
- **VERSION_COMPARE_PROTOCOL_2026-07-15의 "버전 차이(MZ0710↔MZ0713 count-source)" 추론 폐기**: MZ0710에서도 재현 = 버전 무관.
- drift_hunt harness(재부팅 30사이클, MZ0710)가 divergence 0을 낸 이유도 설명됨 — harness가 `is_read=0`을 명시 삽입해 NULL 조건을 안 만들었음.

## 6. 잔여 (dev-side, 단말서 판정 불가)

- **정상 사용 경로로 `is_read=NULL` 부재중이 생기나?** (백업/복원·마이그레이션·특정 provider write 등). 생기면 실 결함(fix 필요), 없으면 툴 아티팩트. 현재 근거상 **실 telephony=is_read=0 → 툴 아티팩트**로 수렴하나, 코드 확인이 최종.

## 7. 개발자 코멘트 초안 (문의 형식, 단정 회피)

**EN / KO 전문**은 세션 기록 참조. 요지: (1) 노말 배지가 알림 수보다 `is_read=0` DB 카운트를 따르는 것으로 관측(알림 5·is_read0 1일 때 배지 1), (2) 툴 삽입 행은 `is_read=NULL`, `is_read=0` 카운트는 이를 제외/ `is_read≠1`은 포함 → 노말↔심플 갭과 정합. 코드상 노말 카운트가 `is_read` 쿼리인지 + NULL 정합화가 MR2 방향인지 **확인 요청**.
