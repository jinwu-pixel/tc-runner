### KO
**BUG #26510 — 부재중 배지 수 불일치 요약**

**현상**: 노말 모드와 심플 모드의 부재중 배지 숫자가 다르게 표시됨 (예: 2 vs 54).

**원인 (쉽게)**: 두 모드가 부재중 개수를 다른 방식으로 셉니다. 각 부재중 기록에는 "읽음/안읽음"을 나타내는 작은 표시값이 있는데 —
- **노말**: 그 표시값이 정상적으로 채워진 기록만 셈
- **심플**: 표시값이 **비어 있는** 기록까지 함께 셈

그래서 표시값이 빈 기록이 있으면 두 숫자가 어긋납니다.

**표시값이 빈 기록은 어디서?**: 실제 전화 착신이 아니라 **테스트 도구가 DB에 직접 넣은 가짜 데이터**에서만 생깁니다. 실제 부재중 전화는 항상 표시값이 채워져, 두 모드가 똑같이 셉니다.

**실 사용자 영향**: **없음.** 문제 데이터가 자동 생성 도구로 만든 것임을 고객과 확인했고, 실사용에서는 재현되지 않습니다.

**성격**: 다만 두 모드가 "빈 표시값"을 다르게 처리하는 것은 **코드상 실제 불일치**로, 양쪽을 맞추면 정리됩니다(수정 규모 작음).

**결정 문의**: 실 사용 영향이 없는 점을 감안해, 이 정합 수정을 **MR2에 포함할 계획인지** 또는 우선순위를 낮춰도 되는지 판단 부탁드립니다.

### EN
**BUG #26510 — Missed-call badge count mismatch (summary)**

**Symptom**: The missed-call badge shows different numbers in Normal vs Simple mode (e.g., 2 vs 54).

**Cause (plain terms)**: The two modes count missed calls differently. Each missed-call record carries a small "read/unread" marker —
- **Normal** counts only records whose marker is properly set
- **Simple** also counts records whose marker is **empty/missing**

So when some records have an empty marker, the two numbers diverge.

**Where do empty-marker records come from?**: Only from **a test tool that inserts fake data directly into the database**, not from real incoming calls. Real missed calls always have the marker set, so both modes count them identically.

**Real-user impact**: **None.** We confirmed with the customer that the affected data was tool-generated; it does not reproduce in real usage.

**Nature**: Still, the two modes handling the empty marker differently is a genuine code inconsistency that can be cleaned up by making both count the same way (small fix).

**Decision needed**: Given there's no real-user impact, please advise whether to include this alignment fix in **MR2**, or whether it's acceptable to deprioritize.
